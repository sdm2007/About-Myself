Overview

Shoppers search for a product or service and see nearby shops with opening hours, stock status and listed prices, without needing an account. Shop owners register, verify their email and manage their own listing.

The frontend is React with Tailwind and Vite, served by a Node.js and Express backend. Data lives in Supabase Postgres, shop photos in Supabase Storage, and the site runs on Render.

Key features

  • Search across shops, categories and individual items
  • Live GPS location, a map of nearby shops and the shortest route (Leaflet and OpenStreetMap)
  • Market price range that compares the same item across shops
  • Stock labels worked out from quantity: in stock, low and out of stock
  • Opening hours, with a one-day "closed today" override
  • Home service radar for repair and service providers
  • Owner dashboard for profile, inventory, hours and photos
  • Email verification, admin approval of new shops and admin review of photos
  • English and Hindi interface
  • Privacy policy, terms and cookie consent

Overview

Shiyank is a team prototype of a water quality tester. Water runs through a pipe past four probes: pH, TDS, turbidity and temperature. An ESP32 reads them and shows the results on a display on the front of the box.

It is an educational screening prototype, not a certified drinking-water safety device. Hardness is tested separately with a drop-test kit, because a TDS sensor cannot give calcium or magnesium hardness.

How the box is arranged

  • Wet side (back). The pipe runs from the inlet on one side to the outlet on the other. All four probes sit inside it through sealed fittings.
  • Partition plate. Separates the pipe from the circuit. The sensor boards are mounted on its dry face, so only the probes touch water.
  • Dry side (front). The ESP32 reads the sensor boards and drives the front display. A USB port on the side supplies 5 V.

Each module gets 3.3 V or 5 V as its datasheet says, and all grounds are joined. Pin numbers are illustrative, so check the datasheets for the exact modules you buy.

Build steps

  1. Test the ESP32Upload a Blink or Serial Monitor sketch before adding any sensor.
  2. Add the temperature sensorDS18B20 to 3V3, GND and GPIO 4, with the 4.7 kΩ resistor from DATA to 3V3.
  3. Add pH, TDS and turbidityOne module at a time. Measure each OUT pin with a multimeter first (3.3 V maximum) and read raw ADC values before converting them.
  4. Add the displaySDA to GPIO 21 and SCL to GPIO 22. If the screen stays blank, scan for the I²C address.
  5. CalibrateUse fresh pH 4 and pH 7 buffers and the TDS reference solution. Rinse the probes with distilled water between samples and note the date of each calibration.

The firmware

The ESP32 runs an Arduino sketch built around a three-state sample cycle. The whole circuit also runs in the Wokwi simulator, where potentiometers stand in for the pH, TDS and turbidity modules.

For now it reports raw sensor voltages. Calibration is what turns them into pH, TDS and turbidity values.

NO SAMPLE→SETTLINGwaits 5 s→MEASURINGreads every 2 s
  • A sample switch on GPIO 27 tells the ESP32 when water is present. In the simulation it is a push-button: pressing it starts a sample and releasing it clears the old readings.
  • Presses are debounced for 50 ms, so one press is read once.
  • Each analogue sensor is averaged over 20 ADC readings and converted to a voltage between 0 and 3.3 V.
  • The DS18B20 temperature is read on GPIO 4. If the sensor is missing, the display and Serial Monitor show an error instead of a number.
  • Results go to a 128×64 SSD1306 OLED (I²C, address 0x3C) and to the Serial Monitor at 115200 baud.
const unsigned long SETTLING_TIME = 5000;     // ms
const unsigned long READING_INTERVAL = 2000;  // ms

enum SampleState { NO_SAMPLE, SETTLING, MEASURING };

// switch pressed = sample present
if (stableButtonState == LOW && sampleState == NO_SAMPLE) {
  sampleState = SETTLING;
  sampleStartTime = millis();
}
// switch released = sample removed
else if (stableButtonState == HIGH && sampleState != NO_SAMPLE) {
  sampleState = NO_SAMPLE;
}

// settled long enough, start measuring
if (sampleState == SETTLING && millis() - sampleStartTime >= SETTLING_TIME) {
  sampleState = MEASURING;
}

Libraries: OneWire, DallasTemperature and Adafruit SSD1306 (with Adafruit GFX).

Safety notes

  • Never feed more than 3.3 V into an ESP32 input pin. Use the interface boards for every probe instead of wiring a probe straight to a GPIO.
  • Keep the ESP32, display and wiring dry. Use waterproof fittings where the probes enter the pipe and keep the plate sealed.

Overview

Notes and previous-year papers end up scattered across chat groups and drives. Learnocrat puts them in one place, organised by course, semester and subject. I built it under the name Prior Art for the SLAB WebCMD Hackathon, and it is still in development.

Uploads are processed in the background. Text is pulled out of PDFs, Word files, text files and images (with OCR for scans), then Claude suggests the subject, type, exam and year. The uploader reviews it before anything is published.

Key features

  • Upload PDF, DOCX, TXT and image files up to 20 MB
  • Text extraction, with OCR for scanned pages
  • AI classification into subject, content type, exam type, year and professor
  • A review step, so nothing is published until the uploader confirms
  • Duplicate checks using file hashes and similar-resource suggestions
  • Search by filters, keywords or a plain-language AI question
  • Karma system: earn karma for uploads, spend it on downloads after three free ones
  • Voting, comments, reporting and admin moderation
  • Background job queue with retries
